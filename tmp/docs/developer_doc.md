Аннотация

Данный документ описывает программную структуру программного комплекса, предназначенного для регистрации виртуальных датчиков, настройки их параметров и запуска тестовых сценариев в среде ROS Noetic и Gazebo. Руководство предназначено для разработчиков, осуществляющих сопровождение проекта, расширение перечня поддерживаемых датчиков и развитие механизмов автоматизированного тестирования.

В документ включены ключевые элементы системы: общая архитектура, состав пользовательского интерфейса, основные backend-модули, а также описание наиболее значимых функций фронтенда и бэкенда. Автоматически обновляемые поля и внешние зависимости документа исключены, вследствие чего документ может использоваться как самостоятельное и редактируемое описание проекта.

# Архитектура

Диаграмма системы и ее описание

Рисунок 1. Диаграмма архитектуры

Архитектура системы построена по модульному принципу и включает четыре логических уровня. Верхний уровень представлен настольным пользовательским интерфейсом на базе PyQt5. Интерфейс реализован в каталоге `front/` и объединяется главным окном `Main_UI`, в составе которого находятся панели выбора датчиков, отображения параметров, запуска тестов и просмотра результатов.

На уровне прикладной логики располагаются классы `SensorRepository`, `QueueManager`, `TestRunner` и `Core`. `SensorRepository` обеспечивает доступ к локальному хранилищу SQLite и отвечает за операции чтения и записи сведений о датчиках и тестах. `QueueManager` управляет очередностью запуска тестовых сценариев и предотвращает одновременное выполнение конфликтующих задач. `TestRunner` выполняет тестовые функции в отдельном потоке исполнения. `Core` предоставляет интерфейсу унифицированный набор операций для работы с датчиками, параметрами и тестами.

Уровень интеграции с внешней средой реализован модулем `Simulator` из `src/gazebo_simulator.py`. Указанный модуль запускает `roscore`, инициализирует ROS-ноду, формирует рабочую сцену Gazebo и предоставляет API для управления моделями, сценами и захватом данных. Через данный слой обеспечивается взаимодействие с ROS-топиками, SDF-моделями датчиков и world-файлами Gazebo.

Нижний уровень составляют данные и ресурсы проекта: база `sensor_storage.db`, конфигурационные файлы `config.py` и `config.yaml`, SDF-модели датчиков, world-сцены и тестовые модули из каталога `src/tests/`. Именно этот уровень задает поддерживаемые типы датчиков, перечень доступных тестов и ресурсы симуляции, используемые при выполнении сценариев.

Технологический стек проекта включает Python, PyQt5, SQLite, ROS Noetic, Gazebo, OpenCV, NumPy, PyYAML и XML/SDF. Выбранный стек обеспечивает совместную работу графического интерфейса, локального хранилища данных, симулятора и инструментов обработки сенсорной информации.

## 2.1 Интерфейс системы

Интерфейс приложения строится вокруг класса `Main_UI` и предоставляет пользователю единое рабочее пространство для управления датчиками и запуском тестов. После запуска приложения выполняется загрузка данных из базы, формируется список датчиков и становятся доступны основные операции: добавление типа датчика, добавление экземпляра датчика, просмотр параметров, запуск тестов и анализ результатов.

На уровне интерфейса наиболее важны четыре класса:

- `ColSensors` отвечает за отображение типов датчиков и экземпляров датчиков.

- `ColTests` формирует список доступных тестов и отправляет выбранные тесты в очередь.
- `ColCapture` принимает результаты и логи, а также отображает полученные данные и диагностические изображения.

## 2.2 Backend системы

Backend обеспечивает хранение данных, регистрацию типов датчиков, запуск симуляции, выполнение тестов и передачу результатов обратно в интерфейс. Основные backend-модули расположены в каталоге `src/`, а часть прикладной логики реализована в модулях `front/logic_*.py`.

Ключевые backend-компоненты:

- `config.py` загружает и валидирует конфигурацию приложения.
- `sensor_storage.py` предоставляет слой работы с SQLite.
- `core.py` предоставляет единый API для интерфейса.
- `sensor.py` описывает модель датчика и базовые операции чтения данных.
- `gazebo_simulator.py` управляет ROS и Gazebo.
- `src/tests/` содержит тестовые сценарии для разных семейств датчиков.

Описание самой функции

Функция анализирует текст SDF-файла и пытается извлечь темы публикации датчика по тегам плагина, пространству имен и remap-аргументам. Она используется для автоматического заполнения сведений о датчике и сокращает объем ручного ввода при добавлении нового сенсора.

Функция `Sensor.capture_data(self, msg_type, topic: str = "", window: float = 2.0, timeout: float = 0.25, warmup: float = 0.0, simulator=None) -> list`

Аргументы функции

- `msg_type` - класс ожидаемого ROS-сообщения.
- `topic` - имя целевого топика; если параметр пустой, используется основной топик датчика.
- `window` - длительность окна сбора сообщений.
- `timeout` - таймаут ожидания одного сообщения.
- `warmup` - задержка перед началом чтения сообщений.
- `simulator` - ссылка на объект симулятора.

Возвращаемые значения функции

- список сообщений, полученных из ROS-топика за время наблюдения.

Описание самой функции

Метод является базовой точкой чтения данных практически для всех тестов. Он собирает сообщения в течение заданного окна, а затем при наличии объекта симулятора передает результаты в интерфейс для отображения кадров и диагностических данных. На его основе реализованы проверки камер, тактильных датчиков и RFID-сценарии.
